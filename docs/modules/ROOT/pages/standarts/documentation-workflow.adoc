= Процесс документирования эндпоинта

Activity-диаграмма того, как происходит документирование нового эндпоинта — от
получения задачи до публикации. Дополняет xref:standarts/discovery-template.adoc[]
(что именно спрашивать у стейкхолдеров) и xref:standarts/endpoint-standart.adoc[]
(в каком формате оформлять результат).

[plantuml]
....
@startuml
start
:Получить задачу на документирование эндпоинта;
:Изучить контракт (код / OpenAPI-черновик);

if (Информации достаточно?) then (нет)
  :Провести интервью со стейкхолдером\n(см. discovery-template);
endif

:Составить черновик по стандарту оформления\n(endpoint-standart);
:Проверить примеры запросов вручную\n(curl / Postman);

if (Примеры воспроизводятся?) then (нет)
  :Зафиксировать расхождение\nи вернуться к стейкхолдеру;
  stop
endif

:Отправить на ревью разработчику;

if (Есть замечания?) then (да)
  :Внести правки;
  stop
else (нет)
endif

:Обновить OpenAPI-спеку, если нужно;
:Смержить и опубликовать;
stop
@enduml
....

Ключевая точка процесса — узел «Примеры воспроизводятся?». Именно здесь чаще
всего всплывает разрыв между тем, что описано в контракте, и тем, что реально
возвращает API — и именно поэтому проверка примеров вручную идёт до, а не после
ревью у разработчика.
