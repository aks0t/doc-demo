= Создание / редактирование лида

Тест-кейсы на форму создания и редактирования лида в Admin UI. Форма отправляет
`POST /leads` (создание) и `PATCH /leads/{id}` (редактирование) — см.
xref:api/endpoints/leads.adoc#_post_leads[Leads API].

== Таблица кейсов

[cols="1,3,3,3,1,1"]
|===
| ID | Предусловия | Шаги | Ожидаемый результат | Приоритет | Тип

| TC-FORM-01
| Пользователь авторизован, открыта форма создания лида
| 1. Заполнить `fullName`, `email`, `phone` корректно +
2. Выбрать `source` = `website_form` +
3. Нажать «Сохранить»
| Лид создан (`201 Created`); открывается карточка лида со статусом `new`; данные совпадают с ответом API
| High
| Позитивный

| TC-FORM-02
| Пользователь авторизован, открыта карточка существующего лида
| 1. Изменить `fullName` и `phone` +
2. Нажать «Сохранить»
| Изменения сохранены (`PATCH /leads/{id}` → `200 OK`); значения обновлены в карточке и в списке
| High
| Позитивный

| TC-FORM-03
| Пользователь авторизован, открыта форма создания лида
| 1. Заполнить `fullName` и `phone` +
2. Оставить `email` пустым +
3. Нажать «Сохранить»
| Под полем `email` отображается ошибка валидации; форма не отправлена; запрос `POST /leads` не выполняется
| High
| Негативный

| TC-FORM-04
| Пользователь авторизован, открыта форма создания лида
| 1. Заполнить `email` значением `not-an-email` +
2. Заполнить остальные поля корректно +
3. Нажать «Сохранить»
| Под полем `email` отображается ошибка «Неверный формат email»; форма не отправлена; API не вызывается
| High
| Негативный

| TC-FORM-05
| Пользователь авторизован, открыта форма создания лида
| 1. Заполнить `phone` значением `12345` (не в формате E.164) +
2. Остальные поля корректны +
3. Нажать «Сохранить»
| Под полем `phone` отображается ошибка «Телефон должен быть в формате E.164 (например, +79991234567)»; форма не отправлена
| Medium
| Негативный

| TC-FORM-06
| Пользователь авторизован, открыта форма создания лида
| 1. Заполнить `fullName` очень длинным значением (например, 300 символов, контракт не задаёт лимит) +
2. Остальные поля корректны +
3. Нажать «Сохранить»
| Форма не ломается: если API принимает значение — лид создан; если API вернул `validation_error` — ошибка показана под полем без потери введённых данных

| Граничный

| TC-FORM-07

2. Остальные поля корректны +
3. Нажать «Сохранить»
| Под полем `email` отображается «Лид с таким email уже существует»; запрос `POST /leads` вернул `409 duplicate_email`; намеренно не показан generic-баннер «Something went wrong»

| Негативный

| TC-FORM-08

2. Остальные поля корректны +
3. Нажать «Сохранить»
| Под полем `source` отображается ошибка валидации с перечислением допустимых значений (`website_form`, `phone_call`, `partner`, `manual`); запрос не отправляется
| Medium
| Негативный

| TC-FORM-09

| 1. Проверить состояние кнопки «Сохранить»
| Кнопка «Сохранить» находится в состоянии disabled; она активируется только после заполнения всех обязательных полей корректно
| Medium
| UI

| TC-FORM-10
| Пользователь авторизован, открыта форма создания лида, `email` и `phone` невалидны
| 1. Нажать «Сохранить»
| Фокус установлен на первом невалидном поле в порядке обхода формы; ошибки отображаются под каждым невалидным полем
| Low
| UI

| TC-FORM-11
| Пользователь авторизован, открыта форма создания лида
| 1. Проверить наличие связанных `<label>` у полей формы +
2. Ввести невалидные значения и отправить форму +
3. Пройтись по форме с клавиатуры (Tab/Shift+Tab)
| У всех полей есть label; ошибки валидации объявляются и привязаны к полю (`aria-describedby`, `role="alert"`); фокус после отправки переходит на первое невалидное поле; форма полностью доступна с клавиатуры
| Medium
| Accessibility

== Связь с API

* Обязательные поля и форматы — xref:api/endpoints/leads.adoc#_модель_данных[Leads API],
  раздел «Модель данных» (`fullName`, `email` — обязательные; `phone` — E.164;
  `source` — из перечисления).
* `409 duplicate_email` — xref:api/errors.adoc#_коды_ошибок_бизнес_логики[Ошибки и коды состояния]
  (TC-FORM-07).
* `validation_error` с указанием поля — TC-FORM-03…06, TC-FORM-08.

== Примечания

Кейсы TC-FORM-09 и TC-FORM-10 проверяют корректное поведение элементов формы
(доступность кнопки, фокус и подсветку ошибок) — это часть функциональной
проверки интерфейса.
