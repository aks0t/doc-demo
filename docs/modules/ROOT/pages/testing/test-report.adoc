`TC-STATUS-05`/`TC-STATUS-06` → BR-002, `TC-FORM-09` → BR-003.

Два дефекта относятся к отображению ошибок API в UI и не блокируют основные
сценарии работы со списком и карточкой лида. Третий связан с состоянием
кнопки формы и не влияет на данные.

== Вывод

**Не готово к релизу** — три открытых дефекта. Два severity Major связаны с
некорректным отображением ошибок контракта (`duplicate_email`,
`invalid_status_transition`) и должны быть исправлены до выката; третий
(BR-003, severity Minor) — в очереди на исправление и не блокирует релиз:

1. BR-001: отображать сообщение `duplicate_email` под полем email.
2. BR-002: отображать сообщение `invalid_status_transition` у элемента выбора
   статуса.
3. BR-003: отключить кнопку «Сохранить», пока обязательные поля не заполнены.

После исправления BR-001 и BR-002 — повторный прогон кейсов `TC-FORM-07`,
`TC-STATUS-05`, `TC-STATUS-06` и закрытие дефектов. Для BR-003 — повторный
прогон `TC-FORM-09`.
