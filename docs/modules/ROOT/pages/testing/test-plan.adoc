= Test Plan

Документ описывает план тестирования условного веб-интерфейса (Admin UI) поверх
CRM Leads API. Структура близка к IEEE 829 / ISTQB, но адаптирована под объём
этого репозитория.

== Цель и границы

=== В рамках (in scope)

* Функциональное тестирование экранов Admin UI:
  ** форма логина;
  ** список лидов (фильтр по статусу, пагинация);
  ** форма создания и редактирования лида;
  ** смена статуса лида.
* API-smoke тестирование по коллекции `qa/api-tests/crm-leads-smoke.postman_collection.json`.
* Кросс-браузерность и адаптивность (по чек-листу).

=== Вне рамок (out of scope)

* Нагрузочное тестирование — API учебный, лимиты задокументированы, но
  производительность не является целью.
* Security-тестирование (пентест) — проверяется только корректность работы с
  токенами (401/403), глубокая безопасность не входит в объём.
* Автоматизация UI-тестов (например, Selenium/Playwright) — на данном этапе
  применяется ручное тестирование.

== Объект и версии

* Объект: Admin UI поверх CRM Leads API (см. xref:testing/overview.adoc#_объект_тестирования[Обзор]).
* Версия API: `1.0` (см. xref:api/overview.adoc#_общие_сведения[Обзор API] и `CHANGELOG.md`).

== Критерии входа и выхода

=== Вход (entry criteria)

* Доступно окружение staging с запущенным API.
* Задокументирован контракт (`openapi/openapi.yaml`) — тест-кейсы построены по нему.
* Тестовые данные подготовлены (минимум 1 лид в каждом статусе).

=== Выход (exit criteria)

* Все тест-кейсы severity High выполнены.
* Нет открытых критических багов (severity Critical/Blocker).
* Все найденные дефекты заведены в баг-репорты (xref:testing/bug-reports.adoc#_severity_vs_priority[Bug-reports]).
* Отчёт по прогону сформирован (xref:testing/test-report.adoc#_результаты[Test report]).

== Окружения

Подробный чек-лист — на странице xref:testing/checklists.adoc#_cross_browser_адаптив_чеклист[Чек-листы].
Минимальный набор:

* Chrome (последняя стабильная), Windows 11;
* Firefox (последняя стабильная), Windows 11;
* Safari (последняя стабильная), macOS;
* 1 мобильный viewport (например, iPhone SE / 375px) в Chrome DevTools.

== Роли

Проект выполняется одним человеком, который совмещает роли:

* test design — написание тест-кейсов;
* test execution — прогон по чек-листам и кейсам;
* test reporting — формирование отчёта и баг-репортов.

== Риски и допущения

* **UI не реализован физически.** Тест-кейсы написаны как спецификация
  ожидаемого поведения интерфейса на основе OpenAPI-контракта. Это допущение
  явно зафиксировано в xref:testing/overview.adoc#_объект_тестирования[Обзоре].
* **API может быть недоступен.** Для UI-кейсов это не блокер — проверяется
  отображение ошибок сети.
* **Rate limiting (429).** Тесты учитывают лимит 120 req/min
  (xref:api/overview.adoc#_rate_limiting[Rate limiting]); при flaky-результатах
  проверяется, не превышен ли лимит.
