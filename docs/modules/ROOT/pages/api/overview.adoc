= Обзор API

== Общие сведения

* Базовый URL: `https://api.example-crm.dev/v1`
* Формат данных: JSON (`Content-Type: application/json`)
* Аутентификация: Bearer-токен (см. xref:guides/authentication.adoc[Аутентификация])
* Даты — в формате ISO 8601, UTC (`2026-07-27T09:00:00Z`)
* Идентификаторы — строки вида `ld_XXXX`

== Пагинация

Списочные эндпоинты поддерживают query-параметры:

[cols="1,1,3"]
|===
| Параметр | Тип | Описание

| `page`
| integer
| Номер страницы, по умолчанию `1`.

| `pageSize`
| integer
| Размер страницы, по умолчанию `20`, максимум `100`.
|===

== Rate limiting

API ограничивает частоту запросов для защиты от перегрузки. Лимит действует на
каждый клиент (`clientId`) независимо.

[cols="1,3"]
|===
| Параметр | Значение

| Лимит
| 120 запросов в минуту на клиента

| Заголовки ответа
| `X-RateLimit-Limit` — общий лимит (120), +
`X-RateLimit-Remaining` — остаток запросов в текущем окне, +
`X-RateLimit-Reset` — Unix-время (секунды), когда окно сбросится

| Код ответа при превышении
| `429 Too Many Requests`, тело ошибки — `{"error": {"code": "rate_limit_exceeded", "message": "Too many requests"}}`
|===

При получении `429` следует дождаться сброса окна (см. `X-RateLimit-Reset`),
затем повторить запрос. Рекомендуемая стратегия — линейная retry-логика с учётом
заголовка `Retry-After`.
